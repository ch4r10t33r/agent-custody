# Working in this repository

This is a Bun workspace. `packages/receipts` is the receipts package, `packages/state` is the governed-memory package. The root README lists packages and layout; each package has its own README. `bun run test`, `typecheck`, and `demo` at the root run across packages; the CLI and tutorials run from inside `packages/receipts`.

- **The READMEs must reflect every change before it is committed.** The package README for the package touched, and the root README when the layout or package list changes. In `packages/receipts/README.md` check, at minimum: the intro, the doc links, the supported hosts table, the quick start, the layout block, and the Plan section (move finished items to Done, renumber Next). Do not commit code that a README describes differently.
- The guides under `packages/receipts/docs/` are part of the change, not a follow-up. A new adapter, command, flag, or check gets documented in the same commit.
- Every Cedar example in `packages/receipts/docs/policies.md` is executed by `packages/receipts/test/docs-policies.test.ts`. Edit them together.
- Every file in a package's `examples/` is executed by that package's `test/examples.test.ts` and must end by printing `OK`. A new module or adapter gets an example in the same commit, plus a row in `docs/tutorials.md` for receipts.
- Consumers install compiled output. Each package has `tsconfig.build.json` emitting `dist/` with declarations and an `exports` map in its package.json; a new public module is added to `src/index.ts`, and a new adapter gets its own `./sdk/<name>` subpath. Pack with `bun pm pack`, not `npm pack`, so `workspace:*` dependencies are rewritten to versions. To publish: bump the version, `bun run build`, `bun pm pack` in the package directory, then `npm publish <tarball> --access public` from a terminal with `NPM_TOKEN` set to a granular npm token that has the 2FA bypass; the gitignored project `.npmrc` reads it. Publish receipts before state.
- Framework adapters are tested against the real package with a scripted model and no network. Do not add an adapter with only a hand-written stand-in. The same rule holds for `packages/python`: its tests run with `uv run --extra test pytest` against a sidecar started from `packages/receipts/src/cli.ts`, and every receipt they produce is checked by the TypeScript verifier.
- `packages/receipts/examples/languages/<lang>` holds one complete sidecar client per language, run by `test/languages.test.ts` against a sidecar in its own process; a missing toolchain skips that language visibly. Tests that run a client synchronously must not host the sidecar in-process, or the client hangs.
- Record-only adapters evaluate no policy. Enforce or observe, never both on one tool.
- `issue`, `record`, and `handleHookEvent` are asynchronous because the log may be remote. A log that refuses a leaf is an error and no bundle is written; never swallow it except where a framework cannot await, and then print it.
- Money is integer minor units; Cedar has no floats.
- The CLI runs on plain Node 22 via native type stripping: no parameter properties, no enums, `.ts` import specifiers. The state package imports the receipts package through its `exports` map, `@agent-custody/receipts` or `@agent-custody/receipts/sdk/<name>`, which resolves to `dist/`; the state typecheck and test scripts build receipts first, and running a state example by hand needs `bun run build` at the root.
- Commit messages carry no attribution trailers.
- `site/` is the website, generated from the repository markdown by VitePress. Root README sections it includes are fenced by `<!-- #region name -->` markers; keep those markers when editing. `bun run site:build` must pass; it fails on dead links.
