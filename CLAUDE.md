# Working in this repository

This is a Bun workspace. `packages/receipts` is the receipts package, `packages/state` is the governed-memory package. The root README lists packages and layout; each package has its own README. `bun run test`, `typecheck`, and `demo` at the root run across packages; the CLI and tutorials run from inside `packages/receipts`.

- **The READMEs must reflect every change before it is committed.** The package README for the package touched, and the root README when the layout or package list changes. In `packages/receipts/README.md` check, at minimum: the intro, the doc links, the supported hosts table, the quick start, the layout block, and the Plan section (move finished items to Done, renumber Next). Do not commit code that a README describes differently.
- The guides under `packages/receipts/docs/` are part of the change, not a follow-up. A new adapter, command, flag, or check gets documented in the same commit.
- Every Cedar example in `packages/receipts/docs/policies.md` is executed by `packages/receipts/test/docs-policies.test.ts`. Edit them together.
- Every file in a package's `examples/` is executed by that package's `test/examples.test.ts` and must end by printing `OK`. A new module or adapter gets an example in the same commit, plus a row in `docs/tutorials.md` for receipts.
- Consumers install compiled output. Each package has `tsconfig.build.json` emitting `dist/` with declarations and an `exports` map in its package.json; a new public module is added to `src/index.ts`, and a new adapter gets its own `./sdk/<name>` subpath. Pack with `bun pm pack`, not `npm pack`, so `workspace:*` dependencies are rewritten to versions. To release: bump the three versions and edit the two workspace `"version"` lines in `bun.lock` by hand; never delete and regenerate the lockfile, which re-resolves dependencies and has broken vitest before. To publish: bump the version, `bun run build`, `bun pm pack` in the package directory, then `npm publish <tarball> --access public` from a terminal with `NPM_TOKEN` set to a granular npm token that has the 2FA bypass; the gitignored project `.npmrc` reads it. Publish receipts before state.
- Framework adapters are tested against the real package with a scripted model and no network. Do not add an adapter with only a hand-written stand-in. The same rule holds for `packages/python`: its tests run with `uv run --extra test pytest` against a sidecar started from `packages/receipts/src/cli.ts`, and every receipt they produce is checked by the TypeScript verifier.
- `packages/python` requires Python 3.10 (the `mcp` client needs it); `agent_custody/memory.py` talks to the state package's HTTP memory server, whose tests need `bun run build` first, which `bun run test:python` does. The mcp Python result flag is `is_error`.
- `packages/receipts/examples/languages/<lang>` holds one complete sidecar client per language, run by `test/languages.test.ts` against a sidecar in its own process; a missing toolchain skips that language visibly. Tests that run a client synchronously must not host the sidecar in-process, or the client hangs.
- Record-only adapters evaluate no policy. Enforce or observe, never both on one tool.
- `issue`, `record`, and `handleHookEvent` are asynchronous because the log may be remote. A log that refuses a leaf is an error and no bundle is written; never swallow it except where a framework cannot await, and then print it.
- Money is integer minor units; Cedar has no floats.
- The CLI runs on plain Node 22 via native type stripping: no parameter properties, no enums, `.ts` import specifiers. The state package imports the receipts package through its `exports` map, `@agent-custody/receipts` or `@agent-custody/receipts/sdk/<name>`, which resolves to `dist/`; the state typecheck and test scripts build receipts first, and running a state example by hand needs `bun run build` at the root.
- **Nothing is pushed to main until `bun run ci` has passed locally.** It runs exactly what the GitHub workflow runs: typecheck, every test suite, the site build, and the Python suite. `.githooks/pre-push` enforces it; enable it once per clone with `git config core.hooksPath .githooks`. Never gate a commit on a filtered test output (`bun run test | grep ...` reports grep's exit code, not the tests'); run the command bare and let it fail the step.
- Commit messages carry no attribution trailers.
- `packages/receipts/vectors/` are conformance vectors: regenerate with `bun run vectors` only when the receipt format or a check changes, and commit the result; never regenerate to make a failing test pass. `site/verifier/verify-web.ts` is the browser verifier and must keep passing every vector; when a check is added or renamed in `src/verify.ts`, mirror it there.
- `packages/state/src/stores.ts` adapters are typed structurally (no runtime import of `mem0ai` or `@getzep/zep-cloud`); their tests use the real client packages against fake HTTP endpoints, with `MEM0_TELEMETRY=false` so the Mem0 client stays offline. Write order in the server is validate, stores, ledger; retract order is ledger, then stores.
- `packages/state/src/server.ts` reads `agent-custody/receipt`, `agent-custody/agent`, and `agent-custody/observed` from the call's `_meta`; the gateway sets them and the agent cannot. Keep the key strings identical in both packages; state duplicates them on purpose to avoid a runtime import.
- `packages/receipts/src/upstream.ts`: an upstream signs `{ receiptId, tool, contentDigest }` where contentDigest is over `{ content, isError }` only, never `_meta`. The browser verifier mirrors the check. The site's early-access form mails `partha@charioteerconsulting.com` unless `ENDPOINT` in `EarlyAccess.vue` is set to a form service.
- A pruned log line is `{"pruned":"<leaf hash hex>"}`; `MerkleLog` reads it as the hash. The receipts package exports `./cli` so the state CLI can spawn the gateway for `sweep --via`. Forget digests: `sha256` (default), `hmac-sha256` with a forget key held outside the file, or `none`.
- `site/` is the website, generated from the repository markdown by VitePress. Root README sections it includes are fenced by `<!-- #region name -->` markers; keep those markers when editing. `bun run site:build` must pass; it fails on dead links.
